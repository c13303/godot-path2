==============================================================================
 RTS MODE: Unit Selection + Multiple Flow Fields (GDExtension)
==============================================================================

This project does NOT use RTS-style unit selection in normal gameplay. The
player controls a single character directly (WASD/ZQSD via Controls).

However, the C++ GDExtension still fully supports the RTS pattern: select a
group of agents with a drag-box and steer that group toward a goal using a
per-group flow field. This document explains how to drive that capability if
you ever want to re-enable it (a new project, a debug mode, or a separate
RTS prototype).

The GDScript glue that used to wire this up (SelectionController,
SpawnController) was removed from the scene. The native systems it called are
unchanged. This doc is the replacement reference.

------------------------------------------------------------------------------
 1. The native nodes involved
------------------------------------------------------------------------------

Under the "CPP" node in scenes/main/mainRun.tscn:

  AgentManagerNative   - registers agents, owns group ids, tracks orders
  FlowFieldNative      - computes/holds flow fields (one per goal/group)
  SteeringSystemNative - moves agents along their group's flow field
  SpatialGridNative    - broad-phase neighbor queries
  PathfinderNative     - path queries

Agents that participate in group movement must:
  - be a Node2D
  - be added to the "main_chars" group (so selection can find them)
  - be registered with AgentManagerNative.spawn_agent(node, kind) -> nav_id

------------------------------------------------------------------------------
 2. Spawning a group-controllable agent
------------------------------------------------------------------------------

  var agent: Node2D = AGENT_SCENE.instantiate()
  parent_for_agents.add_child(agent)
  agent.global_position = spawn_pos
  agent.add_to_group("main_chars")

  # Register with the native manager. Returns a navigation id.
  var nav_id: int = int(agent_manager.call("spawn_agent", agent, 0))
  agent.set("nav_id", nav_id)

Notes:
  - The 2nd arg (kind = 0) is the agent class/kind used by the native side.
  - Keep nav_id on the node; it's the handle for steering/profile calls.
  - For placement, query walkable cells via the floor/wall TileMapLayers
    (floor tile present AND no wall tile) to avoid spawning inside walls.

------------------------------------------------------------------------------
 3. Groups
------------------------------------------------------------------------------

A "group" is an integer id minted by the manager. All agents assigned to the
same group share one flow field / one goal.

  # Make a fresh group:
  var group_id: int = int(agent_manager.call("create_group"))

  # Assign an agent to a group:
  agent_manager.call("assign_agent", unit, group_id)

  # Tell the manager which group the UI currently has selected:
  agent_manager.call("set_current_selected_group", group_id)

  # Mark that a group has been given an order (used by steering/idle logic):
  agent_manager.call("mark_group_has_order", group_id)

  # Drop empty/stale groups before creating a new selection:
  agent_manager.call("cleanup_groups")

Typical selection flow:
  1. cleanup_groups()
  2. group_id = create_group()
  3. for each unit inside the drag-box: assign_agent(unit, group_id)
  4. set_current_selected_group(group_id)

------------------------------------------------------------------------------
 4. Drag-box selection (screen-space)
------------------------------------------------------------------------------

Selection is done in SCREEN space, so convert each agent's world position with
the canvas transform before hit-testing the rectangle.

  var xform: Transform2D = get_viewport().get_canvas_transform()
  for node in get_tree().get_nodes_in_group("main_chars"):
      if node is Node2D:
          var screen_pos: Vector2 = xform * node.global_position
          if rect.has_point(screen_pos):
              # this unit is inside the selection box
              ...

Building the rect from a mouse drag:
  - On left-button press: record start = get_viewport().get_mouse_position()
  - While held: rect.position = min(start, mouse), rect.size = abs(mouse-start)
  - On release: run the selection test above with the final rect.
  - Ignore tiny rects (e.g. size < 3px on both axes) so a click isn't a drag.

A green translucent ColorRect on a CanvasLayer makes a good visual box
(mouse_filter = MOUSE_FILTER_IGNORE so it doesn't eat input).

Optional hover-preview while dragging: highlight units currently inside the
box by calling unit.set_previewed(true) (or modulate them), and clear the
highlight on the units that leave.

------------------------------------------------------------------------------
 5. Multiple flow fields (one goal per group)
------------------------------------------------------------------------------

Each group gets its OWN flow field aimed at its OWN goal. The native side
keeps these separate keyed by group id, so several groups can move to
different destinations at the same time.

Assign a goal to the currently selected group (right-click in world):

  func _on_click_set_goal(group_id: int, world_pos: Vector2) -> void:
      if group_id < 0:
          return
      agent_manager.call("mark_group_has_order", group_id)

      # Snap goal to the tile center for stable field computation:
      var local_pos: Vector2 = floorz.to_local(world_pos)
      var cell: Vector2i = floorz.local_to_map(local_pos)
      var center: Vector2 = floorz.to_global(floorz.map_to_local(cell))

      # Build/assign a flow field for THIS group toward the goal:
      if flow.has_method("assign_flow_to_group"):
          flow.call("assign_flow_to_group", group_id, center)

Each call to assign_flow_to_group(group_id, goal) updates only that group's
field. Issue it once per group to have N groups pathing to N goals.

Lower-level FlowFieldNative API (see scripts/pathfinder/FlowFieldCode.gd):
  ff.set_floor_layer(floor_layer)
  ff.set_wall_layer(wall_layer)
  ff.compute_distance_field_global()
  ff.compute_flow_dir(world_pos)       # sample direction at a point
  ff.rebuild_async(goal_world_pos)     # recompute toward a goal off the main thread

------------------------------------------------------------------------------
 6. Steering / per-agent tuning
------------------------------------------------------------------------------

Agents in a group follow their group's flow field automatically once the
SteeringSystem is running. For per-agent behavior the native steering exposes
(same calls Controls uses for the player):

  steering.set_agent_control_mode(nav_id, mode)   # 1 = manual, else flow-driven
  steering.set_agent_manual_motion(nav_id, accel, decel)
  steering.set_agent_input(nav_id, dir)           # manual move vector
  steering.set_agent_profile(nav_id, profile_dict)
  steering.set_paused(bool)

Profile dictionary keys (from the player setup, all optional):
  crowd_push_strength, world_radius, foot_offset_y,
  fight_offset_y, fight_half_w, fight_half_h, smash_class, max_speed

For RTS group movement you generally do NOT set manual control mode; you leave
agents flow-driven and only assign group flow fields.

------------------------------------------------------------------------------
 7. Putting it together (minimal RTS controller sketch)
------------------------------------------------------------------------------

  # left release -> selection
  cleanup_groups()
  current_group = create_group()
  for unit in units_inside(rect):
      assign_agent(unit, current_group)
  set_current_selected_group(current_group)

  # right click -> goal for selected group
  if current_group >= 0:
      mark_group_has_order(current_group)
      assign_flow_to_group(current_group, snapped_goal)

  # spawn more units into the current group
  nav_id = spawn_agent(new_unit, 0)
  assign_agent(new_unit, current_group)

 8. Where the old code lived (for git archaeology)
------------------------------------------------------------------------------

Removed in favor of single-character control:
  scripts/controls/selection_controller.gd  (drag-box + group assignment)
  scripts/controls/spawn_controller.gd       (spawn into walkable cell + group)
  scripts/controls/fx_controller.gd          (empty stub)

These were children of the "Controls" node and were gated behind the
Controls.enable_mouse_unit_commands flag (default false). Recover them from
git history if you want a working starting point rather than the API sketch
above.
